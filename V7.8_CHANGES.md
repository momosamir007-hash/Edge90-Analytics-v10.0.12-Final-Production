# Edge90 Analytics v7.8 — Walk-Forward Validation Engine

## Goal
v7.8 adds a rolling, expanding-window validation layer so model improvements are judged across multiple chronological origins instead of one fixed holdout.

## What changed
- Added `Backtester.run_walk_forward()`.
- Uses strictly chronological expanding windows.
- Each fold reruns the existing leakage-safe pipeline independently.
- Aggregates evaluation-weighted Log Loss, Brier score, result accuracy and draw accuracy.
- Reports Meta-Learner activation rate and Calibration 2.0 activation rate across folds.
- Added `LeagueApp.run_walk_forward_backtest()` for application-level use.

## Why this matters
A single holdout can make a version look better merely because of one favorable evaluation period. Walk-forward validation checks whether gains persist through several historical periods.

## Interpretation
Lower Log Loss and Brier are better. Result and draw accuracy are secondary diagnostics. A new layer should not be considered an improvement unless its gains are stable across folds.
